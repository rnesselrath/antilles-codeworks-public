Data Access, Storage & Retention

App Name: Smart Release Report (Jira Cloud App)

Last Updated: November 2026

This page is a technical reference to the Privacy Policy, which is the primary notice for data handling and privacy requests.

1. Data Access & Processing

Forge functions retrieve Jira data to help the current user review and prepare release notes. The app accesses:

  • Project and version data: Project names, keys and IDs, and version names, IDs and release status, so users can choose what to review.
  • Issue data: Issue keys, summaries, issue types, statuses, priorities, components, labels, fix versions and project information. Where available, the app also reads the Jira team field and Jira field and priority metadata.
  • Current-user access: Jira and Confluence API requests are made as the current user and are subject to that user's permissions.

Forge functions retrieve Jira data and read or write app-side release decisions and project settings. The app's browser interface processes the returned Jira data and release notes. When the user opens the Confluence publishing flow, the app can retrieve Confluence spaces and pages to select a destination. If the user requests publication or an update, it sends the release-note content to the selected Confluence page. The app does not ask users to provide passwords or API keys.

2. Storage Locations

The app uses Forge-hosted storage for release decisions and project settings, and browser storage for review preferences:

  • Release decisions: Edited summaries, per-issue category overrides, Internal work and Technical wording overrides, and Include/Exclude decisions are stored in Forge-hosted Key-Value Store. These records are scoped to the relevant Jira project and release; issue-level records also identify the Jira issue.
  • Project settings: Configured release categories, issue-type-to-category mappings, and issue types marked as always internal are stored in Forge-hosted Key-Value Store for the Jira project.
  • Generated release notes: Release notes are prepared in the browser and are not separately stored by the app in Forge-hosted storage. If the user requests publication, the content is sent to the selected Confluence page.
  • Preferences: Browser local storage holds preferences for the Jira site and project: selected version, sort field and order, category, label and review-signal filters, and selected Confluence space and parent page. Label and signal filters are associated with the version they were set on. These settings are not stored in Forge-hosted storage.
  • External services: The current app manifest does not declare an external backend, external network destinations, or an analytics service. This describes the current implementation and may change in a future app version.

3. Retention & Deletion

  • Individual overrides: Users can reset a saved summary to the Jira summary and return category, Internal work, or Technical wording overrides to Automatic; these actions remove the corresponding override from Forge-hosted storage. Include/Exclude decisions can be changed, but the app currently has no separate action to reset that decision to its default. Contact the developer through the Privacy Policy for deletion requests concerning remaining app-stored data or project settings.
  • Forge-hosted data after uninstall: Atlassian states that Forge-hosted data is retained for 60 days following the end of the billing or trial period after uninstall, unless the customer removes the app immediately and forfeits the remaining retention period. A reinstall is treated as a new installation; a request to relink to previous data may be made within 21 days of uninstall. See Atlassian's Forge storage data lifecycle for current details.
  • Browser preferences: Uninstalling the app does not remove preferences in browser local storage. Users can clear them through their browser's site-data settings.
