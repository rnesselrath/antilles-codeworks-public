Security Statement

App Name: Release Report (Jira Cloud App)

Last Updated: October 2026

Security Summary: Release Report is an Atlassian Forge app. Its backend functions run on Forge, and its user interface runs in the browser within Jira. The app uses Jira and Confluence APIs as the current user and stores summary overrides in Forge-hosted storage. User preferences are stored in the browser's local storage. The app manifest does not declare an external backend or external network destinations.

1. Cloud Architecture & Infrastructure

The app uses Atlassian Forge for its backend functions and Atlassian product APIs:

  • No declared external backend: The app manifest does not configure an external backend, analytics service, or external network destination. The app does use Forge-hosted storage for summary overrides.
  • Forge backend: Backend functions run on Atlassian Forge. The app's user interface runs in the browser, so some data is processed there as part of the user's interaction.
  • Product API access: The app accesses Jira and Confluence through Atlassian APIs using the current user's permissions.

2. Data Access & Permissions (Principle of Least Privilege)

The app declares the following OAuth scopes in its manifest:

  • read:jira-work: Used to retrieve Jira project, version, and issue data for release notes.
  • read:space:confluence and read:page:confluence: Used to retrieve Confluence spaces and pages for choosing a publishing destination.
  • write:page:confluence: Used to create or update a Confluence page when the user requests publication.
  • storage:app: Used to save and retrieve summary overrides in Forge-hosted storage.

3. Data Storage & Encryption

  • Summary overrides: User-edited issue summaries are stored using Forge-hosted Key-Value Store, scoped to the app installation.
  • Preferences: Settings such as the selected version, sorting options, and Confluence destination are stored in the browser's local storage. They are not stored in Forge-hosted storage and may remain in the browser after the app is uninstalled.
  • Data in use: Jira and Confluence data needed for the current workflow is returned to and processed by the app's browser interface. Users can copy generated release notes or request that the app publish them to Confluence.
  • Credentials: The app does not ask users to provide passwords or API keys. Requests to Jira and Confluence use Atlassian's current-user authentication.
  • Forge storage protection: Forge-hosted storage is provided and managed by Atlassian. Refer to Atlassian's Forge storage documentation for details about its storage and data lifecycle.

4. Vulnerability Management & Platform Updates

Atlassian operates the Forge platform infrastructure. The app's source code and dependencies are maintained by its developer. This statement does not represent a guarantee that every dependency is continuously audited or that vulnerabilities cannot occur. Security-relevant updates to the app should be reviewed and deployed by the developer.
