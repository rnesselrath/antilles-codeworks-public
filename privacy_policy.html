Privacy Policy for Release Report

Last Updated: October 2026

1. Overview

Release Report ("the App") is an Atlassian Forge application that helps users select Jira project versions, review and format related issues as release notes, and optionally publish those notes to Confluence. This is the App's primary privacy notice. The Data Access, Storage & Retention page provides a technical summary of the same data flows, and the Security Statement describes the App's security architecture and contact route.

2. Architecture & Data Transfers

The App is built on Atlassian Forge. Forge functions make Jira and Confluence API requests as the current user and use Forge-hosted storage for summary overrides. The App's interface also processes data in the user's browser. In the version covered by this policy, the App manifest does not declare an external backend, external network destinations, or an analytics service.

  • Atlassian services: Jira and Confluence API requests are made as the current user and are subject to that user's Atlassian permissions. Forge-hosted storage is provided by Atlassian.
  • Browser processing: Jira data and preferences are handled by the App's browser interface. Users may copy generated release notes or request that the App publish them to Confluence.
  • Scope of this statement: These details describe the current implementation and may change in a future version. The App does not control how a user handles copied content or content after it is published to Confluence.

3. Data Processed by the App

To generate and manage release notes, the App may process the following Jira information:

  • Project and version data: Project names, keys and IDs, and version names, IDs and release status, to let the user choose what to review.
  • Issue data: Issue keys, summaries, issue types, statuses, priorities, components, labels, fix versions and project information. Where available, the App also reads the Jira team field. It requests field and priority metadata to support issue display and sorting.
  • Summary overrides: Replacement issue summaries entered by a user. These are stored in Forge-hosted Key-Value Store as described below.

When a user opens the Confluence publishing flow, the App can retrieve Confluence spaces and pages to let the user choose a destination. If the user requests publication or an update, the App sends the release-note content to the selected Confluence page.

4. Personal Information

The App does not request Jira user names, email addresses or IP addresses as fields for release-note generation. Jira issue summaries, labels, team-field values, overrides, or other Jira content may nevertheless contain personal information. Such content may be processed in the browser and, for summary overrides, in Forge-hosted storage. The App's current implementation does not declare an external backend or external network destination. Users should avoid including personal information in release notes unless appropriate for their use case.

5. Data Storage & Retention

  • Summary overrides: User-edited issue summaries are stored in Forge-hosted Key-Value Store, associated with the App installation. The App currently has no user-facing function to delete an individual override. To ask about deletion of Forge-hosted overrides, contact the developer using the details below.
  • Generated release notes: Release notes are prepared in the browser and are not separately stored by the App in Forge-hosted storage. If a user requests publication, the content is sent to the selected Confluence page and is then subject to the customer's Confluence configuration and applicable Atlassian terms.
  • App preferences: The browser's local storage holds preferences for the Jira site and project, including the selected version, sort field and order, issue categories, technical-issue and technical-wording filters, and the selected Confluence space and parent page. These preferences are not stored in Forge-hosted storage and are not deleted when the App is uninstalled. Users can clear them through their browser's site-data settings.
  • Uninstallation: Atlassian states that Forge-hosted data is retained for 60 days following the end of the billing or trial period after uninstall, unless the customer removes the App immediately and forfeits the remaining retention period. A reinstall is treated as a new installation; a request to relink to the previous data may be made within 21 days of uninstall. See Atlassian's Forge storage data lifecycle for current details.

6. Permissions (OAuth Scopes)

The current App manifest requests the following scopes for its features:

  • read:jira-work: To retrieve Jira project, version and issue data.
  • read:space:confluence and read:page:confluence: To retrieve Confluence spaces and pages for destination selection.
  • write:page:confluence: To create or update a Confluence page when the user requests publication.
  • storage:app: To store and retrieve summary overrides using Forge-hosted storage.

7. Privacy Requests & Applicable Law

For questions or requests concerning summary overrides held by the App, contact the developer using the details below. Jira data and published Confluence content remain subject to the customer's Atlassian configuration and applicable Atlassian terms. The use of Atlassian Forge does not by itself establish compliance with the General Data Protection Regulation (GDPR) or other privacy laws. The customer and developer should assess their respective obligations based on the data and circumstances in which the App is used. Users should ensure that personal information included in Jira content or release notes is handled appropriately.

This notice does not specify a legal basis, a postal address, or a jurisdiction-specific complaints process. Those details depend on the publisher's legal identity and operating circumstances and should be confirmed by the publisher before relying on this notice for legal compliance.
